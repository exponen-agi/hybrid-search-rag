Hybrid Search RAG: How It Works

A visual walkthrough of the recipe recommender in this repository. If you'd rather run code than read diagrams, jump straight to the notebook or the README.

1. The problem: keyword search vs. meaning search

Say a user searches for "warm soup for a cold day". Two very different search techniques can answer this, and each one is good at something the other is bad at.

Dense / semantic search

Turns text into a vector (a long list of numbers) that captures meaning. "Warm soup" and "Pumpkin Bisque" end up as similar vectors, even though they share no words. Great at understanding intent — but can occasionally drift away from an exact word the user cares about.

Sparse / keyword search

Classic full-text search (this project uses TF-IDF). Matches exact words. Very precise for specific ingredient or dish names — but has zero understanding of meaning, so it misses synonyms and paraphrases entirely.

Hybrid search runs both searches at once and merges the two ranked lists using Reciprocal Rank Fusion (RRF) — a simple, well-tested algorithm that rewards results appearing near the top of either list. Qdrant does this fusion natively in a single query.

The same Qdrant collection stores both vector types per recipe — a semantic-vector (dense, 3072 numbers from Gemini) and a keyword-vector (sparse, from TF-IDF). One query, one round trip, one fused answer.

3. What happens on a single search, step by step

sequenceDiagram
    actor User
    participant Tool as RecipeSearchTool
    participant Gemini as Gemini Embeddings
    participant TFIDF as TF-IDF Vectorizer
    participant Qdrant
    participant Agent as CrewAI Agent (Gemini LLM)

    User->>Agent: "best thai recipe for winter"
    Agent->>Tool: call hybrid_search(query)
    Tool->>Gemini: embed_query(query)
    Gemini-->>Tool: dense vector (3072 dims)
    Tool->>TFIDF: transform(query)
    TFIDF-->>Tool: sparse vector
    Tool->>Qdrant: query_points(prefetch=[dense, sparse], fusion=RRF)
    Qdrant-->>Tool: top-k fused recipe matches
    Tool-->>Agent: formatted recipe list
    Agent-->>User: friendly recommendation

5. Scaling the dataset

The notebook includes an opt-in cell that uses Faker to generate a mock dataset of any size, so you can see how indexing time and search latency change as the collection grows — all the way up to 1,000,000 recipes.

5 recipes → instant 20,000 recipes → ~45s indexing 1,000,000 recipes → ~35–40 min, Qdrant Cloud recommended

Qdrant's own in-memory mode prints a warning past ~20,000 points — for a genuine 1,000,000-recipe benchmark, point the notebook at a real Qdrant Cloud cluster or a local Qdrant Docker container instead of :memory: mode.
